# LLM From Scratch

A from-scratch implementation and measurement study of the language-modeling
stack — tokenizer, Transformer pretraining, GPU systems optimizations,
pretraining data, and post-training — with a technical report for each part.
Everything is written from primitives (no `nn.Transformer`, `flash_attn`,
DeepSpeed, or TRL in the implementations under test), and every number in the
reports is regenerated by scripts from the raw run records rather than
transcribed.

## Projects

| [transformer-lm](transformer-lm/) | Byte-level BPE tokenizer, decoder-only Transformer (RMSNorm, RoPE, SwiGLU, causal attention), AdamW with warmup + cosine schedule, training loop, sampling decoder | Bit-exact BPE against the reference tokenizer (4.18 bytes/token on TinyStories); a 22.7M-parameter model reaches 1.57 validation loss in 1.5 GPU-hours; controlled sweeps and four ablations, incl. the finding that a 1000×-too-large learning rate still ends at a finite loss because the cosine tail rescues it | [PDF](transformer-lm/report/tech_report.pdf) |
| [training-systems](training-systems/) | Profiling and kernel attribution (Nsight Systems), mixed precision, gradient checkpointing, Triton FlashAttention-2 (forward + backward), three DDP variants with communication overlap, ZeRO-1, FSDP, analytic scaling limits | 5.7× attention speedup at 64K context (bf16), and the only tested implementation that fits FP32 at 64K; overlap cuts the gradient-communication share of a step from 69% to 59% on 4 GPUs; −43% steady-state memory from a from-scratch FSDP within 14% of PyTorch's | [PDF](training-systems/report/tech_report.pdf) |
| [data-pipeline](data-pipeline/) | Common Crawl WET → pretraining corpus: extraction, language ID, PII masking, harmful-content classifiers, Gopher quality rules, fastText quality classifier, exact + MinHash/LSH dedup, sample-level audit | 2.14M documents → 9.3% kept → 340M GPT-2 tokens; paired 4000-step ablation: −0.27 nats C4-100 validation loss (perplexity 282 vs 367); an audit documenting each filter's failure modes, and a scale study showing when a data ablation measures memorisation instead of data quality | [PDF](data-pipeline/report/tech_report.pdf) |
| [post-training](post-training/) | GRPO from scratch for reasoning RL; SFT + DPO preference optimization; verifier-quality study; engineering notes against real-world RL frameworks | GRPO report: the prompt, not the estimator, is the first-order variable at 1B scale; clipping in the off-policy surrogate is load-bearing; RL retains ~90–105% of its gain under a 10%-flip verifier where test-time selection retains 57%, with an affine-invariance mechanism for the asymmetry. SFT/DPO report: most of the MMLU gain from instruction tuning is answer format; the AlpacaEval winrate of the same model swings 3.8% → 33.2% depending on the judge | [PDF](post-training/report/tech_report.pdf), [PDF](post-training/report_track3/tech_report.pdf) |

raw run records (`report/make_figures.py` and its companions), so the tables
cannot drift from the data they summarise.

## Running the code

Each project is an independent `uv` project with a pinned lockfile; there is no
workspace or shared environment:

```bash
cd transformer-lm   # or training-systems / data-pipeline / post-training
uv sync
uv run pytest
```

Notes:

- CPU test subsets run anywhere; the GPU paths (Triton kernels, distributed
  training, vLLM rollout) need a CUDA machine — each project's README says which
  is which.
- The large training runs were executed on a shared 6×A6000 node; nothing here
  requires that scale to be reproduced at a smaller one.

## Scope and provenance

These projects are implementation and replication studies. The methods they
reproduce are published work and are cited in the reports; the acknowledgement
of scope in each report states which parts follow published designs and which
are original, and no result is transcribed by hand — the numbers come from
scripts reading the run records that ship with the repository.
